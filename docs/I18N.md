# Languages

The source strings of the app are Spanish. Every other language is a `.ts`
file in `i18n/` compiled to `.qm` and embedded into the binary under `/i18n`.
There is no Linguist step in the build: the `.qm` files are committed.

```
i18n/lotus-tune_en.ts   English, all 460 strings
i18n/lotus-tune_en.qm   what the app loads
i18n/lotus-tune_es.ts   Spanish, only the three plural strings
i18n/lotus-tune_es.qm
```

The Spanish file looks odd but is needed: Qt cannot build `%n canción` for the
source language without a catalogue, so without it "1 canción" and "3
canción" both came out with the wrong form. `Translator` loads the `.qm` of
whatever language is chosen, the source one included.

## Adding a language

1. Create the catalogue, translate it and compile it:

   ```
   lupdate6 -source-language es -target-language fr -no-obsolete qml/ src/ \
            -ts i18n/lotus-tune_fr.ts
   lrelease6 i18n/lotus-tune_fr.ts -qm i18n/lotus-tune_fr.qm
   ```

2. Rebuild. `CMakeLists.txt` globs `i18n/*.ts`, checks that each one has a
   `.qm` no older than it and embeds the pair. `Translator::available()` lists
   the `.qm` files it finds at runtime, so the picker in Ajustes shows the new
   language on its own.

3. The name of the language in the picker comes from `Translator::name()`.
   Common codes are written out there ("English", "español", "日本語"); the
   rest fall back to `QLocale`, which may answer with the territory included
   ("français" is fine, "American English" is not).

The build refuses to package a `.qm` older than its `.ts`
(`IS_NEWER_THAN` in `CMakeLists.txt`): a stale one is a language that half
works. `tools/update-translations.sh` regenerates both files after the source
strings change.

## What does not come from the `.ts`

The Android side has its own strings: the label of the app, the media
notification, the lyrics widget and the notice of a new version. They live in
`android/src/main/res/values/strings.xml` (Spanish) and `values-en/` (English),
and the phone picks one by its own language, not by the choice inside the app.

## Checking it without a phone

```
lotus-tune --lang=en --i18n-selftest
```

Prints a handful of strings, the plural ones included, and exits. `--lang`
forces the language for one run without touching the saved choice.
`lotus-tune --lang=system` follows `LANG`.
